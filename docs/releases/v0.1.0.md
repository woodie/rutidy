# rutidy v0.1.0

## Initial release

`rutidy` brings RSpec/Mocha/Vitest-style output to RSpec itself, matching the same
four looks `gorderly` (Go), `xctidy` (Swift), and `kotidy` (Kotlin) already share.
Unlike those three, it isn't a text post-processor -- `Rutidy::Formatter` is a real
RSpec formatter that hooks the same `example_group_started`/`example_group_finished`
notifications RSpec's own `--format documentation` formatter uses internally, so
every example's nesting comes from the real stack RSpec maintains, not a guess.

## `Rutidy::Formatter`

A structured JSON report -- same field set as stock `rspec --format json`
(`description`, `full_description`, `status`, `file_path`, `line_number`,
`run_time`, `pending_message`, `exception`), plus the one field that format is
missing: `hierarchy`, a real per-level array of every enclosing `describe`/
`context`'s description down to the example itself.

## `rutidy` (the CLI)

Four named styles (`classic` default, `-fd`, `-fs`, `-fv`), matching `gorderly`'s
own table. Wraps `rspec` directly (`rutidy spec/`), reads an existing report file
(`rutidy report.json`), or reads a piped report from stdin -- the same "wrap the
CLI or read its report" duality `gomeleon` offers for Ginkgo.

See the README for the full styles table and usage, `docs/COWORK.md` for why a
real formatter beats a text post-processor for RSpec specifically.
